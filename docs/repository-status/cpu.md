# CPU、地址保护与 xv6 加速

`src/cpu.rs` 保存寄存器、PC、U/S/M 特权级、CSR、周期和 LR/SC 保留。CPU 通过 `MemDevice` 访问内存与设备；公开运行入口为 `Machine::step/run`，每步先推进设备，再执行 CPU。

## 已实现行为

- 复位进入机器模式；按指令长度取指并更新 PC，保持 `x0=0`。
- 异常与中断按 `MEDELEG/MIDELEG`、特权级和使能位路由；机器模式异常不向下委托。陷入与 `sret/mret` 维护状态位、返回地址和原因寄存器。
- 支持 16 项 PMP、TOR/NA4/NAPOT、锁定、最低编号优先及完整访问范围检查。
- 支持 Bare 和 Sv39，检查规范地址、保留位、页权限、SUM/MXR、超级页对齐和 A/D 位；页表读写和最终访问均检查 PMP。
- Sstc 根据 `TIME >= STIMECMP` 产生监督模式定时器中断。
- LR/SC 记录物理地址、宽度和内存页版本。SC 消费保留；CPU 存储、异常入口及同页 DMA 写入均可使其失效。默认 MMIO 不支持 LR/SC。

页表常量与编码函数集中在私有的 `src/paging.rs`。DRAM 通过同一个页大小定义限制保留区域，避免重复定义页表位和页大小。

## xv6 兼容加速

`src/cpu/xv6_accelerator.rs` 集中实现可选的 xv6 内核函数加速，原有 `cpu::Xv6Accelerator` 导入路径保留。普通 CPU 默认关闭加速，用户态始终执行原始指令。已删除仅凭地址识别并提前返回的用户态 `exec` 特例。

字符串和内存操作每次最多处理 1 MiB，页表遍历最多访问 256 个页表页、处理 256 个叶子映射，超限后执行原始指令。稀疏虚拟空洞直接跳过，预算按实际工作量计算。`strlen` 有扫描上限；`memmove` 临时缓冲最多占用 1 MiB。`freewalk` 先检查整棵树的范围、叶子、重复页和页数，再释放页面；字节填充循环按预算分批执行。

`set_xv6_accelerator` 返回 `Result`，拒绝无效内存范围、进程表范围、全局对象或函数入口。正式 `xv6` 装载模块另行核对提交版本、源码状态和镜像校验值。直接使用底层配置的库调用方仍须保证函数与固定结构布局匹配。

## 限制

- 单硬件线程、同步访存，每步固定推进 10 个周期；没有多硬件线程或异步内存模型。同步顺序执行满足当前模型的 aq/rl 顺序要求，但尚无多硬件线程验证。
- 没有 TLB 或地址翻译缓存；每次访问重新遍历页表，因此 `sfence.vma` 当前无需清除缓存。PMP 未实现 Smepmp 等扩展。
- xv6 内核加速会合并多条指令，不能用于验证精确的指令时序或中断发生位置；可关闭加速检查原始执行路径。
- `ebreak` 进入架构异常入口，不是宿主停机协议。
