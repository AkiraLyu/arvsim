# CPU、内存保护与 xv6 加速

`src/cpu.rs` 保存寄存器、程序计数器（PC）、U/S/M 特权级、CSR、周期数和 LR/SC 保留信息。CPU 通过 `MemDevice` 访问内存与设备。对外运行入口是 `Machine::step/run`，每步先更新设备状态，再执行 CPU 单步。

## 已实现的功能

- 复位后进入机器模式。根据指令长度读取指令并更新 PC，始终保持 `x0=0`。
- 根据 `MEDELEG/MIDELEG`、当前特权级和中断使能位选择异常或中断处理入口。机器模式发生的异常不会交给更低特权级处理。进入处理程序及执行 `sret/mret` 时，会更新状态位、返回地址和原因寄存器。
- 支持 16 项物理内存保护（PMP）配置，包括 TOR/NA4/NAPOT 地址匹配、配置锁定和完整访问范围检查。多个区域匹配时，优先使用编号最小的项。
- 支持不进行地址转换的 Bare 模式和 Sv39 分页。检查虚拟地址格式、保留位、页面权限、SUM/MXR、大页对齐及 A/D 位。页表读写和转换后的内存访问都要经过 PMP 检查。
- 支持 Sstc。启用相应功能后，`TIME >= STIMECMP` 会产生监督模式定时器中断。
- 支持 LR/SC。LR 记录内存区域的物理地址、访问宽度和页写入版本号；SC 检查这份保留记录，尝试结束后清除记录，无论写入成功与否。CPU 存储、进入异常处理程序或同页 DMA 写入都可能使保留失效。默认 MMIO 设备不支持 LR/SC。

页大小、页表位和页号转换函数统一放在内部模块 `src/paging.rs`。DRAM 使用同一个页大小来划分 LR/SC 保留区域。

## xv6 内核加速

`src/cpu/xv6_accelerator.rs` 实现可选的 xv6 内核函数加速，配置类型仍通过 `cpu::Xv6Accelerator` 使用。直接创建 CPU 时默认关闭加速。用户程序始终逐条执行，不再跳过用户态的 `exec` 调用。

字符串和内存操作每次最多处理 1 MiB。页表操作每次最多访问 256 个页表页、处理 256 个叶子映射；未建立映射的虚拟地址区间会被跳过，上限按实际处理量计算。超过上限时，CPU 改为执行原始指令。`strlen` 的扫描长度有上限，`memmove` 的临时缓冲最多占用 1 MiB。

`freewalk` 在释放页表前，先检查整棵页表树的地址范围、叶子映射、重复页和页数。字节填充循环按每步上限分批执行。

`set_xv6_accelerator` 返回 `Result`，拒绝无效的内存范围、进程表范围、全局对象地址和函数入口。库中的 `xv6` 模块还会检查源码版本、源码是否修改以及镜像校验值。直接设置加速配置的调用方，需要自行保证函数地址与固定版本的数据结构布局一致。

## 已知限制

- 只模拟一个硬件线程，内存访问同步完成，每步固定增加 10 个周期。当前按程序顺序执行，满足这一模型下的 aq/rl 顺序要求，但尚未验证多硬件线程的情况。
- 没有地址转换缓存（TLB），每次访问都重新查询页表，因此 `sfence.vma` 当前无需清除缓存。PMP 尚未支持 Smepmp 等扩展。
- xv6 内核加速会把多条指令合并处理，不能用于验证精确的指令时序或中断发生在哪条指令之间。可以关闭加速，检查原始指令的执行结果。
- `ebreak` 会进入被模拟程序的断点异常处理程序，不会直接停止模拟器。
