# `src/csr.rs`：控制与状态寄存器

## 功能

`Csr` 用一个包含 4096 项的 `u64` 数组保存 12 位地址空间内的 CSR 状态。`SSTATUS`、`SIE` 和 `SIP` 是对应机器模式寄存器的受限访问方式，只显示监督模式允许访问的字段。

CPU 检查指令是否有权访问 CSR。本模块负责保存寄存器、处理别名、限制可写位，并将不支持的写入值调整为实现允许的值（WARL）。硬件产生的待处理中断另行保存。

## 已实现的功能

- 当前 CPU 使用的机器模式和监督模式 CSR、`TIME`、`STIMECMP`、机器标识寄存器，以及 16 项 PMP 配置。
- `SSTATUS` 只显示监督模式可见的字段，VS/FS/XS 固定读取为零。`SIE/SIP` 只显示由 `MIDELEG` 委托给监督模式的中断位。
- 对 `mstatus`、`tvec`、异常和中断委托寄存器、中断寄存器、计数器控制位、`menvcfg`、`xepc`、`satp` 和 PMP 实施写入限制。
- UXL/SXL 固定表示 RV64。`misa` 和未设置的机器标识返回 0；`stimecmp` 复位为 `u64::MAX`。
- 硬件中断与软件写入的 `MIP` 状态分开保存，CSR 读写不会把硬件信号误存成软件状态。`menvcfg.STCE=0` 时，机器模式可写 `mip.STIP`；启用 Sstc 后，旧的软件 STIP 被清除，改由 `stimecmp` 控制定时器中断。
- CPU 检查 CSR 是否实现、地址编码要求的特权级、只读属性，以及 TVM、计数器和 Sstc 的访问条件。不允许的访问会产生非法指令异常。
- PMP 支持 `pmpcfg0/2`、`pmpaddr0..15` 和逐项锁定。锁定 TOR 区域时，用作下界的前一个地址寄存器也会被锁定。

## 公开接口与依赖

模块公开已实现 CSR 的地址、状态位和中断位常量，提供 `Csr::{new, load, store, is_implemented, is_read_only, update_pending, dump_csr}`，并实现 `Default`。

CPU 持有 `Csr`，负责权限检查、进入和退出异常处理程序时的状态切换，以及读取硬件中断状态。指令模块通过 CPU 检查权限后，再调用 `load/store`。PMP 地址匹配由 CPU 完成，相关配置和常量由本模块提供。

## 已知限制

`load/store` 是底层公开接口，不接收当前特权级。直接调用不会进行指令权限检查；对未实现或越界的地址，读取返回 0，写入不改变状态。被模拟程序执行 CSR 指令时，仍会先检查地址和权限。

目前只实现 CPU 所需的部分 CSR，没有 `cycle/instret`、完整性能计数器，以及调试、浮点、向量和虚拟化状态。`misa` 固定为 0，程序无法通过它得知实际支持的 I/M/A/C 指令。PMP 仅支持基础的 16 项配置，没有可配置粒度或 Smepmp 等扩展。

后续可将地址、特权级和读写方式统一交给带检查的 CSR 接口处理，同时保留 CPU 内部更新硬件状态所需的接口。
