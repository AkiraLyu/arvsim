# 测试组织与职责

测试按可观察行为分层：设备模块检查寄存器、DMA、错误和复位语义；CPU 测试检查指令结果、异常与中断；集成测试运行实际程序并检查整机状态。

已删除通用 `TestMachine` 包装和 `tests/support/mod.rs`。两个集成测试文件直接调用正式库：`rv64i_smoke.rs` 保留组装平台和编译汇编输入所需的辅助函数，`xv6_fixture.rs` 只保存机器、UART 及文本等待断言。工具直接通过 `Command` 启动，失败时报告命令错误，不再先调用 shell 探测工具。

测试的预期应来自功能需求或规范。普通重构不应迫使测试跟着内部字段、私有辅助函数、精确遍历页数或暂存结构改变。加速测试从 CPU 正常单步入口执行，检查复制结果、返回地址、无效配置和回退后实际执行的指令；稀疏内存行为由真实 xv6 usertests 验收。

输入构造和故障注入可以放在测试中，模拟器功能仍由正式库实现。明确属于外部约定的边界应保留，例如访存宽度、异常原因、PLIC 寄存器行为、DMA 范围和 ELF 失败时内存不变。重复覆盖同一行为的薄包装测试不再单列。
