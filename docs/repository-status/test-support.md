# 测试分工与编写原则

设备测试检查寄存器、DMA、错误处理和复位结果；CPU 测试检查指令执行、异常和中断；集成测试运行实际程序，检查多个模块共同工作时的结果。

两个平台集成测试文件直接调用库接口。`rv64i_smoke.rs` 中的辅助函数负责创建平台和编译汇编程序；`xv6_fixture.rs` 保存机器与 UART，并等待、检查串口输出。原来的通用 `TestMachine` 包装和 `tests/support/mod.rs` 已删除。外部工具通过 `Command` 直接启动，失败时报告命令错误，不再先启动 shell 检查工具是否存在。

测试的预期结果应来自功能需求或规范。调整内部字段、拆分函数或改变临时数据结构时，只要对外行为不变，测试就应继续通过。加速测试从 CPU 单步入口运行，检查复制结果、返回地址、无效配置是否被拒绝，以及取消本次加速后是否执行原始指令。未映射内存区域的处理通过 xv6 usertests 检查。

测试可以准备指令、页表、设备请求和故障输入，但指令、设备、镜像加载与系统调用等功能必须由库实现。应保留接口或规范要求的边界测试，例如访问宽度、异常原因、PLIC 寄存器规则、DMA 范围，以及 ELF 加载失败时内存不变。只重复已有断言、不增加功能覆盖的用例应删除。
