# `src/instruction.rs`：指令解码与执行

## 执行过程

模块从指令编码中提取操作码、寄存器编号和立即数，再调用对应的执行函数。当前以 32 位值接收取指结果；低两位不是 `11` 时，按 16 位压缩指令处理。执行函数直接读写 `Cpu` 的寄存器、PC、CSR 和总线，并在指令结束时恢复 `x0=0`。

## 支持的指令

- RV64I：基础整数运算、加载和存储、分支、跳转、LUI/AUIPC，以及处理 32 位结果的 W 类指令。
- RV64M：乘法、除法和取余，包括除零、溢出等边界情况。
- RV64A：LR/SC，以及常见的 32 位和 64 位原子内存操作（AMO）。
- 系统指令：CSR 读写、`ecall`、`ebreak`、`sret`、`mret`、`wfi` 和 `sfence.vma`。
- RVC：xv6 使用的常见压缩指令，目前未覆盖整个扩展。
- `FENCE/FENCE.I`：在当前同步、单硬件线程模型中不执行额外操作。同一操作码下未实现或保留的 `funct3` 会产生非法指令异常。

## 编码与控制流

W 类乘除法只接受 `MULW/DIVW/DIVUW/REMW/REMUW` 的合法编码。C.LWSP 的立即数由指令的第 12 位、6:4 位和 3:2 位组合而成。C.LUI 的零立即数属于保留编码，会产生异常；`C.MV rd=x0, rs2!=x0` 属于提示指令（HINT），按空操作执行。

分支和跳转通过 `Cpu::write_pc` 设置下一条指令地址，因此偏移为零时可以停在原地址。`ecall` 根据 U/S/M 特权级产生不同异常。`sret/mret`、`wfi`、`sfence.vma` 和 CSR 指令会检查当前特权级，以及 TSR、TW、TVM 等控制位。

CSRRS/CSRRC 只有在源寄存器为 `x0` 时才省略 CSR 写入；其他源寄存器即使值为零，也会执行写入。CSRRW 在 `rd=x0` 时省略 CSR 读取。立即数形式 CSRRSI/CSRRCI 在立即数为零时省略写入，CSRRWI 在 `rd=x0` 时省略读取。

## 内存访问与原子操作

加载、存储、压缩指令的内存访问和 AMO 都先检查自然对齐，即地址必须是访问字节数的整数倍，再进行地址转换。LR 按读取权限访问支持保留的内存，记录物理地址、访问宽度和页写入版本号。SC 检查并清除保留记录；检查失败时不写入目标地址。

普通存储、其他 AMO 和进入异常处理程序都会清除保留。同一物理页上的 DMA 写入也会使保留失效。`MemDevice::write` 接收 `u64`，因此 8 字节存储和 AMO 只需调用一次设备写入方法。

## 字节填充加速与测试

开启 xv6 加速后，模块可批量执行符合特定指令模式的字节填充循环。如果存储值来自不断递增的指针寄存器，就按原始指令执行，避免把每次不同的值误当成常量填充。填充范围必须位于配置的 DRAM 内，虚拟地址与物理地址必须相同，并且允许写入。

每步最多填充 1 MiB，其余部分留到后续步骤。用于识别循环的指令如果跨页，则使用普通取指方式处理。

测试通过正常单步入口检查立即数、栈偏移、寄存器结果、跳转目标和实际写入的数据，不直接断言私有解码函数、未使用的字段或优化识别结果。

## 公开接口与依赖

- `Instruction` 公开 `opcode/rd/funct3/rs1/rs2/funct7/raw` 字段。
- `decode(u32) -> Instruction`。
- `execute(&mut Cpu, Instruction) -> Result<(), Exception>`。

CPU 调用本模块执行指令，本模块也会直接修改 CPU 状态。内存访问按实际宽度检查地址转换和 PMP 权限；CSR 访问先由 CPU 检查权限。错误使用 `Exception`。批量填充从 `Xv6Accelerator` 读取实际 DRAM 范围，不使用 `cfg` 的默认边界。

## 已知限制与后续改进

当前按程序顺序完成内存访问，尚未验证多硬件线程下的 aq/rl 和内存访问顺序。`wfi` 在权限允许时不执行等待；`sfence.vma` 没有需要清除的 TLB。浮点、向量等扩展尚未实现，`misa` 也未报告当前支持的指令集。

解码、执行、立即数处理和优化仍集中在一个较大的文件中。后续可按 I/M/A/C 和系统指令拆分，并通过 riscv-arch-test、边界测试和属性测试增加覆盖。支持多硬件线程时，还需验证并发原子操作和内存访问顺序。
