# 已知限制与后续计划

本页只记录仍未完成的能力，不重复列出已修复的问题。当前版本面向单硬件线程 xv6 验证，尚未取得完整 RISC-V ISA 或设备符合性验证。

## 指令与特权架构

- 补齐 RVC 和常用 CSR，提供准确的 `misa` 能力声明，并接入 RISC-V 架构测试。现有测试覆盖关键边界，不能证明所有合法编码和 CSR 组合都正确。
- 当前同步、顺序访存满足单硬件线程模型的 aq/rl 顺序要求。增加多硬件线程或异步访问时，需实现并验证内存顺序、跨线程保留失效及中断行为。
- Sv39 每次访问都重新遍历页表，没有 TLB；当前 `sfence.vma` 无缓存需要清除。将来引入 TLB 时，必须同步实现 ASID、失效范围和页表更新约束。
- 保留 Sstc 的 `stimecmp/STIP`，另行实现 CLINT/ACLINT 的软件中断和机器模式定时器。

## 设备与公共接口

- Virtio 目前只有同步块设备和单个 split queue，未提供间接描述符、EVENT_IDX、多队列与异步后端。
- UART 仍是满足当前工作负载的 16550 子集；PLIC 只有电平网关，边沿输入和多硬件线程场景需进一步实现与验证。
- 主命令行目前只暴露基础 DRAM/UART 配置。完整平台及块介质通过库和 xv6 示例使用，后续可统一命令行配置。
- 库仍公开较多 CPU 状态和模块。可按实际调用需求收窄接口，并评估统一访问宽度类型，避免为抽象而增加层次。

## 性能与工程质量

- xv6 内核加速已限制单步工作量，但仍依赖固定结构布局且合并多条指令。应结合基准测试逐步采用通用优化，并保留关闭加速的验证路径。
- ELF 装载器不支持动态链接和重定位；重叠段按程序头顺序装载，也不检查所有链接器布局约束。
- xv6 提交和构建产物均可核验；编译结果仍受工具链版本影响。可进一步固定工具链，并把格式检查、clippy 和验收测试接入持续集成。
- 补充独立 ISA 测试、模糊测试和差分测试，重点覆盖非法指令、页表、CSR 组合及畸形设备输入。

改变指令、设备或加速逻辑后，先运行默认测试，再验证 xv6 启动与用户程序，最后执行完整 usertests。每轮应记录实际结果和是否启用加速，不能沿用旧版本的通过记录。
