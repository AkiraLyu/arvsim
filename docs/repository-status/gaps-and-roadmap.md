# 已知限制与后续计划

本页记录尚未实现的功能和需要补充的测试。当前版本主要用于在单个硬件线程上运行 xv6，尚未完成对 RISC-V 指令集和设备规范的全面验证。

## 指令与特权架构

- 补齐 RVC 和常用 CSR，让 `misa` 准确报告支持的指令集，并接入 RISC-V 架构测试。现有测试只覆盖部分边界情况，不能证明所有合法指令编码和 CSR 组合都正确。
- 当前内存访问同步、按程序顺序执行，满足单硬件线程模型下的 aq/rl 顺序要求。增加多硬件线程或异步访问时，需要验证内存访问顺序、其他线程写入后 LR/SC 保留是否失效，以及中断处理。
- Sv39 每次访问都重新查询页表，没有地址转换缓存（TLB），所以 `sfence.vma` 当前没有需要清除的缓存。引入 TLB 时，需要同时处理地址空间标识（ASID）、缓存清除范围和页表更新后的同步。
- 保留 Sstc 的 `stimecmp/STIP` 支持，另行实现 CLINT/ACLINT 的软件中断和机器模式定时器。

## 设备与公开接口

- Virtio 目前只支持同步块设备和一个 split virtqueue。间接描述符、EVENT_IDX、多队列和异步存储后端尚未实现。
- UART 只实现当前程序用到的部分 16550 功能。PLIC 只处理电平触发的中断，边沿触发和多硬件线程场景仍需实现和验证。
- 主命令行只提供基本的 DRAM/UART 配置。完整平台和磁盘通过库或 xv6 示例使用，后续可统一命令行配置方式。
- 库公开了较多 CPU 状态和模块。后续应根据实际调用需求减少不必要的公开接口，并评估是否需要专门的类型来表示访问宽度。

## 性能与工程改进

- xv6 内核加速已限制每步的工作量，但仍依赖固定的数据结构布局，并会把多条指令合并处理。后续可结合性能测试，逐步采用不依赖 xv6 的优化，同时保留关闭加速的测试方式。
- ELF 加载器不支持动态链接和重定位。地址重叠的段按程序头顺序加载，也没有检查链接器可能使用的全部布局规则。
- xv6 版本和构建文件可以校验，但编译结果仍受工具链版本影响。后续可固定工具链版本，并把格式检查、Clippy 和功能测试加入持续集成流程。
- 补充独立的指令集测试、模糊测试和差分测试，重点检查非法指令、页表、CSR 组合和格式错误的设备输入。

修改指令、设备或加速逻辑后，应先运行默认测试，再检查 xv6 启动和基础用户程序，最后运行完整 usertests。每次都应记录实际结果，并注明是否启用加速。
