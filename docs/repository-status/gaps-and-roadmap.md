# 已知问题与改进计划

本文只列尚未完成的工作。已经完成并有测试证明的事项不再保留。

## P1：理清模块职责

1. 修正 PLIC 的两个规范偏差：claim 必须忽略 threshold；completion 必须按写入目标当前是否 enable 该源决定是否接受，并补充多上下文测试。
2. 为 `Xv6Accelerator` 校验 xv6 提交版本、结构布局、符号范围、DRAM/进程区间和用户程序地址；给字符串、内存与页表快速路径统一设置单步工作和宿主内存预算。
3. 让 ELF 装载器把虚拟 `e_entry` 映射到实际 `PT_LOAD` 物理装载地址，并要求入口属于可执行段；同时考虑装载失败的原子性。
4. 用枚举表示访问宽度，消除设备对非法 `usize` 宽度的重复检查；为 CSR 等安全公共接口封装受检地址。
5. 继续减少公开字段和公开模块，为库提供稳定的构建器、镜像装载、状态观察和运行控制接口。
6. 在主命令行暴露正式 `VirtPlatform`、块介质和交互 UART 配置；当前只有测试与 xv6 交互脚本使用完整平台。

## P2：提升 RISC-V 语义完整性

1. 扩展 CSR 和 PMP 覆盖范围，提供可用的 `misa` 能力声明，并补充性能计数器等通用软件常用寄存器。
2. 为 Sv39 增加 ASID、TLB 和 `sfence.vma` 刷新语义；继续补充跨页访问和页表更新失败的边界测试。
3. 实现 aq/rl 和多硬件线程内存顺序；明确单硬件线程模式下 `wfi` 与中断唤醒的行为。
4. 补齐 RVC，并按 I/M/A/C/system 拆分指令模块；接入 riscv-arch-test，测试并记录实际支持的 ISA。
5. 将 Sstc 与未来的 CLINT/ACLINT 分开：保留 `stimecmp/STIP`，另行实现 `msip/mtime/mtimecmp` 或 ACLINT 对应设备。
6. 修正 virtio-blk 部分 IN DMA 失败时的 used length，预检 DMA 完成元数据；随后扩展异步 I/O、间接描述符、EVENT_IDX 与多队列，并为 PLIC 边沿网关和多 hart 上下文增加规范测试。

## P3：可复现性、性能与工程质量

1. 固定 xv6 提交版本和测试文件校验值；获取失败时默认终止，显式离线复用必须校验并记录实际版本；默认完整性测试应验证 kernel 与 usertests ELF、必需符号和 `fixture.env`。
2. 严格校验 xv6 CLI 的正数 step chunk 和预算，使用不会保留全部 UART 历史的流式输出；再将临时程序改为正式的 Cargo 可执行目标或示例程序。
3. 在现有 `off/pc/full` 调试级别之外提供可注入的跟踪输出接口和交互式调试器，避免核心代码直接打印到标准输出。
4. 先用基准测试确认性能热点，再评估基本块缓存、译码缓存或 JIT，并逐步减少针对 xv6 函数的硬编码加速。
5. 将 `cargo fmt --check` 和 clippy 设为持续集成必检项，并继续加入覆盖率、Miri、模糊测试、属性测试、非法设备输入和脚本环境边界测试。

## 建议验收顺序

每个阶段先运行小型 ISA 和设备测试，再运行 xv6 启动测试，最后运行快速和完整 usertests。正式设备路径的当前长测基准见验证记录；后续改变设备时序或 xv6 加速器时应重新执行，不能沿用测试旁路时代的通过记录。
